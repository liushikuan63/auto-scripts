## 已修复问题

| 严重度 | 问题 | 修复 |
| --- | --- | --- |
| 高 | Alarm Intent 没有 action，接收器忽略正常定时闹钟。 | 调度、立即触发和取消统一使用显式 `WATERING_ALARM` Intent。 |
| 高 | 暂停状态仍接受 Worker/闹钟触发。 | `triggerWateringNow` 只接受 `RUNNING`。 |
| 高 | 手动暂停后回到游戏会被无条件自动恢复。 | 记录“因游戏后台而暂停”的原因，只恢复该状态。 |
| 高 | 状态机持锁执行耗时状态，暂停/停止可能长时间等待。 | 先同步关闭运行标志并取消当前状态协程；超时使用结构化 `withTimeout`。 |
| 高 | OCR 文本块已是中心坐标，点击代码又叠加半宽/半高。 | 直接使用中心坐标，并按截图尺寸缩放校准偏移。 |
| 高 | 区域 OCR 接口完全忽略传入区域，调试页也实际识别整屏。 | 按行/文字边界框与目标区域的交集过滤，调试页改用真实裁剪识别。 |
| 中 | 雕像移动检测调用点击函数，检测到文字时会提前误点。 | 改成只做 OCR 存在性检测。 |
| 中 | 新增走位和齿轮坐标固定为 `1920x1080`。 | 摇杆、阈值、偏移和兜底坐标按截图宽高缩放。 |
| 中 | 周末双倍倒计时以 30 分钟步进，最多偏差约 29 分钟。 | 直接构造下一次周五 18:00，并补精确分钟测试。 |
| 中 | 连续保存配置时异步 DataStore 写入可能乱序。 | 使用持久化 Mutex 和版本号，只保留最新写入。 |
| 中 | 延迟执行的旧状态可能在暂停后快速恢复时重新运行。 | 引入状态转换代次，暂停、停止和新转换会使旧任务失效。 |
| 中 | 暂停会取消 WorkManager 兜底，但恢复后不会重建。 | 调度器改为跟随引擎启动/暂停生命周期。 |
| 中 | 设置页作物列表读取全局旧等级，不响应当前编辑值。 | 将本地 `farmLevel` 显式传入选择器。 |
| 中 | 动态广播接收器对外暴露，内部闹钟接收器也被导出。 | 改为 `RECEIVER_NOT_EXPORTED` 和 Manifest `exported=false`。 |
| 中 | Android 10 调用 API 30 的窗口尺寸接口。 | API 30 以上使用 WindowMetrics，API 29 使用兼容路径。 |
| 中 | 公开仓库缺少 Settings 与 Wrapper，跟踪本机配置和 class 产物。 | 补齐可复现构建文件，移除本机和生成文件的跟踪。 |

## 剩余风险

- 真实游戏 UI、OCR 结果、黑边和设备坐标映射只能通过目标设备验收。
- 项目保留较多历史 Lint warning，主要为日志库风格、未使用资源和最低 API 下的冗余版本判断；它们不阻断当前构建，但应按模块逐批治理。
- “升级后开地”的成功判定仍依赖游戏页面与 OCR 文案，缺少可重复的设备自动化测试。
- 当前对战流程只打开入口并提示用户手动收尾，不是完整的对局自动化。
